# Coverage map

Each concern from the brief, the mechanism that addresses it, and how it is tested. Maintainer-facing: not loaded during coding sessions.

**Type:** *invariant* holds in every mode. *Default* applies unless there's a stated reason not to. *Conditional* applies when its trigger is present.

**Tested by:** `sNN` is a scenario in `evals/scenarios.yaml`. Whether each one actually ran is recorded there and in `evals/RESULTS.md`. `lint` is a deterministic test in `tests/`. A rule is not proven to help just because it is listed: see the results.

## Python coverage, aspect by aspect

Python is the primary target. Other languages get the language-neutral core, including the file size and large codebase section of the design reference, plus a short skill for what differs. TypeScript, Go and Rust also have structure, naming and test result sections, unmeasured. Guidance in `occam-python` is loaded conditionally from `references/`.

**All of this postdates the evaluated plugin.** "Deterministic" means free tests in `tests/test_python_coverage.py` and `tests/test_occam_hook_python.py`, which show the text and the hook behave as stated. They don't show that an agent does better with them. Agent runs for s40 to s46 happened once, on Sonnet: **no measured benefit, and a reference was read in only 1 of 21 plugin runs**, so they say little about the references themselves. See `evals/RESULTS.md`. Direct pointers added after those runs were then tested on five cases: a reference was still read in only 1 of 15 runs, so they don't get it read. The top facts are now stated in hook notes when a trap appears in the code being written, which no run can yet confirm reaches agents.

## Conflicts, resolved in the skill's tie-breakers

| Conflict | Resolution |
|---|---|
| Correctness or minimal diff | Correctness, with the diff as small as a correct fix allows |
| Reuse or a flawed helper | Don't inherit a known defect or insecure habit |
| Plan fidelity or new evidence | Change the plan, keep the goal |
| Persistence or authorization | Authorization. Stop at the boundary and report |
| Parallel speed or ownership | Ownership |
| Thoroughness or context and time cost | Enough to support the claim you make. Otherwise make a smaller claim |
| Less code or safety | Safety. Simplifying doesn't touch validation, data-loss handling, security, accessibility or anything requested |
| Options of equal size | The one correct on edge cases, then the smaller |
