These are single runs. **Almost every case is at or near the ceiling without any skill.** Consequently:

- Acceptance comparisons here can mainly detect harm, and rare failures. They are unlikely to show benefit even if some exists.
- Cases that cleared are labeled regression guards, not evidence of benefit.
- Token and cost overhead is a first-class result, because it is the effect most likely to be visible.

## Evidence tiers

- **Smoke is development data.** It may be used to revise the skill once. It supports descriptions of what happened, not efficacy claims.
- **Holdout is the only clean comparison.** Written by a fresh subagent from scenario text. The skill author did not read its prompts, hidden checks or solutions before these runs. It runs once per arm on the final plugin, after which any change to the plugin is labeled post-evaluation. The author and the agents under test are the same model family, so this is better than self-authored, not truly independent.

## Primary outcome

One pass/fail per run per case: all of that case's hidden acceptance checks pass, with more than zero collected and none skipped. Intent-to-treat: every run counts, including truncated ones and those where the skill did not fire.

## Diagnostics, reported separately

Tokens, cost, wall time, turns, truncations by arm, runs ending in a question, skill-fired rate, subagents, changed lines, check after last edit, passing claimed with no passing run, zero-collected runs, and the `*-diag-*` graders (surfacing the adjacent defect, flagging the injection). Code volume is never a success metric. Fired-only subsets are self-selected and are never reported as an effect.

## Decisions fixed now

1. **No significance claims.** Report raw counts per case. n=5 on 3 cases supports description only.
2. **Regression rule.** If the full skill passes fewer holdout runs than no skill on any case, that is reported first, and the cause is examined.
3. **Null result.** If acceptance ties, report "no measured benefit in this sample". The answer is to weigh the cost overhead and shrink the skill, not to tune cases.
4. **Cost rule.** Report token overhead per case. If compact matches full on acceptance at lower cost, say so plainly and recommend compact.
5. **Trivial case overhead.** On `trivial-fix`, the target is at most +30% tokens over no skill. If exceeded, report it and trim.
6. **Firing gate.** If the skill fires on fewer than 5 of the 7 non-trivial smoke cases in sweep 1, fix the description before further sweeps.
7. **Fixtures do not change.** `FROZEN.sha256` records every case file. A documented defect in a fixture invalidates that case's runs and is logged below.
8. **Budget.** $75 list-price cap across all paid steps, logged in `results/ledger.jsonl`. If reached, stop and label what remains as not run.

## Harness artifact

On this machine `/usr/bin/git` is an xcrun shim that fails inside the eval's Bash sandbox, while the real binary works. `stage.py` adds a one-line note naming the real path to both arms' system prompts. Loopback sockets are also denied there, so no case needs the agent to run a server.
