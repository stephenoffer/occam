# Code review

Every change to production code needs one approving review from someone who didn't write it.
Reviews should happen within one working day; if a change is waiting longer, ask in the team
channel.

Keep pull requests small enough to review in half an hour. Describe what changed and why, and how
you tested it. Reviewers check behaviour and tests first, naming and style last.

Don't merge your own change while a reviewer's question is unanswered.
